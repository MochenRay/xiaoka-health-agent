# C8 跨维度洞察合同

> 目标：为周报、月报和手动综合分析提供静态 prompt 合同。本文只定义输入、门槛、输出和边界，不改 runtime，不解析个人健康数据。

## 输入

C8 读取标准运行时路径：

- `workspace/data/YYYY-MM/DD.json`：近期 daily JSON，作为主要结构化来源。
- `config/profile.md`：用户基础信息、健康边界和可用背景。
- `config/goals.md`：目标体重、热量、宏量和阶段目标。
- `workspace/medical/`：可选，只读取最近体检，并且只在报告目标明确需要医学/体检维度时使用。

周报优先连接以下维度：

- nutrition
- weight
- exercise
- activity_summary
- steps
- sleep

月报可在有明确来源时补充：

- supplements
- medical

不得假装 daily JSON 有每日药物字段。若只存在用药背景，只能作为医学边界或背景，不得写成每日药物-体重/睡眠关联。

## 数据门槛

- 有效 JSON 天数 <3 时，章节结论固定输出：`数据不足，暂不做关联判断。`
- 某个候选关联的配对日 <3 时，只跳过该候选关联，或对该候选关联固定输出：`数据不足，暂不做关联判断。`
- 其他满足门槛的候选关联仍可输出。
- 若没有任何候选关联满足门槛，章节结论使用：`数据不足，暂不做关联判断。`
- 缺失维度写“未记录”或跳过，不补猜。
- 覆盖率、有效天数和配对日数量必须写入依据。

配对日指同一天内两个候选维度都有可用记录。例如要观察“运动与睡眠”，必须至少有 3 天同时有运动或活动记录，以及睡眠记录。

## 输出结构

`## 跨维度观察` 固定使用三段：

```markdown
### 结论

<!-- 当有效 JSON 天数 <3，或没有任何候选关联满足配对日 >=3 时，写：`数据不足，暂不做关联判断。` -->
<!-- 当至少一个候选关联满足门槛时，替换为低断言强度 C8 观察。 -->

### 依据

- 有效 JSON 天数：{X}
- 候选关联配对日：{X}
- 记录情况：{哪些维度已记录，哪些未记录}

### 边界

- 这只是记录层面的观察，不推断确定因果。
- 医学、药物、体检相关内容只作整理和提醒，不构成诊断或处方。
```

数据足够时，结论仍必须使用弱判断：

- “观察到……”
- “可能相关……”
- “值得继续观察……”
- “下周期重点跟踪……”

## 报告接入

周报接入：

1. 先完成覆盖率和单维度汇总。
2. 使用 C8 检查 nutrition / weight / exercise / activity_summary / steps / sleep。
3. 每个候选关联先检查有效 JSON 天数和配对日。
4. 单个候选关联配对日不足时，只跳过该候选或对该候选写固定不足句。
5. 若没有任何候选关联满足门槛，在 `## 跨维度观察` 的结论中写固定句。

月报接入：

1. 先完成覆盖率、月度趋势和必要的月环比门槛。
2. 使用 C8 检查 nutrition / weight / exercise / activity_summary / steps / sleep。
3. 只有当 supplements / medical 有明确来源时，才补充到月度观察。
4. 单个候选关联配对日不足时，只跳过该候选或对该候选写固定不足句。
5. 若没有任何候选关联满足门槛，在 `## 跨维度观察` 的结论中写固定句。
6. 医学、药物、体检相关观察必须写明边界。

## 不做事项

- 不改 runtime。
- 不做 parser。
- 不碰或反向生成个人健康数据。
- 不从缺失字段推断事实。
- 不输出确定因果。
- 不做诊断、处方或药物调整建议。
- 不把 profile 中的用药背景当作 daily JSON 的每日药物记录。
